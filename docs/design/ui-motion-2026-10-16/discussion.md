# PickGloss UI 与动效设计讨论

日期：2026-10-16。

## 当前方向（后续确认优先）

用户在看到第一版样机后补充并重新选择了以下内容，覆盖下文早期记录中关于名称、图标与绿色配色的决定：

- 产品展示名统一为 **PickGloss**，操作文字继续使用中文。
- 底栏收藏、历史只显示图标，保留悬停提示、可访问名称与收藏选中反馈。
- 主图标改为根据汉字「拾」的提手旁与「合」字结构设计；应用图标、悬浮球、托盘和划词入口共用字形。此前气泡版和 P 形版保留为过程资产，均不是当前方向。
- 配色已停止多方案探索。深色使用纯黑主面与银灰白文字；浅色随后按用户要求改为**轻微暖白**，主面为 `#F7F5F1`，不使用绿色。
- 明暗模式提供浅色、深色、跟随系统；窗口材质提供实色、磨砂半透明。预设可保存明暗模式、材质、强调色、底色倾向、不透明度和模糊强度，可保存多套、切换、更新当前预设。
- 正式程序通过「外观与主题」入口即时预览和保存；Windows 支持时使用原生磨砂，不可用或系统要求减少透明时回退实色。实际桌面背景上的观感仍需人工验收。

用户随后确认当前暖白与黑银配色，并确认重画后的「拾」字几何块面图标：保留提手旁和「合」字骨架，使用标准字形与小尺寸校正字形，应用图标、悬浮球、托盘和划词入口同步适配。最新指令为“可以，就用这版图标，把已确认的 UI、主题和动效方案落地到正式程序”，图标与整体方案不再待选。

目前没有必须重新展开的视觉方向问题。设计规范已整理到根目录 `DESIGN.md`。正式程序中的展开／收窄、阅读位置、屏幕变化恢复和减少动态效果按已确认规则实现；检查范围记录保留在本机验收归档。浏览器样机不作为正式程序验收。

本轮图标展示页为样机 `icon-design.html`。最新图标及实际界面证据位于 `evidence/icon-redesign/`、`evidence/icon-redesign-light/`、`evidence/icon-redesign-dark/`，优先于下文早期细线字形截图。

最新截图位于样机 `evidence/monochrome-dark/`、`evidence/monochrome-glass/` 与 `evidence/monochrome-warm-light/`。`monochrome-light/` 是改为暖白之前的银灰浅色。颜色卡片 `color-directions.html` 只保留过程比较，不继续要求用户选择。

意图：在用户已确认的「随手浮窗」方向内精修 UI，统一产品图标，并细化移动、展开收缩和尺寸变化的手感。阶段：图标、主题和动效方案已确认，进入正式程序实施与验证。下文保留早期讨论来源，遇到差异以本文当前方向和根目录 `DESIGN.md` 为准。

## 用户任务与设计目标

用户在其他软件中阅读时，通过 PickGloss 看懂选定内容，必要时继续追问，再回到原来的阅读。

设计目标：轻巧、清晰、跟手的阅读工具。所有设计活动使用 oil-ui-pro；通过 grill-with-docs 引入的 grilling 和 domain-modeling 收敛决策与术语。只在图标和关键动效难以用文字判断时制作原型。

## 已确认的前提

- 已有结构方向为 A「随手浮窗」，沿用已经确认的小窗与阅读视图层级；设计样机只保留在本机，不进入公开仓库。配色与图标以本文「当前方向」为准。
- 沿用已验收的默认窗口尺寸：小窗 300 × 483、阅读视图 860 × 690，均为逻辑像素。此前尺寸、字体同步调整和恢复操作的确认保留在本机验收归档。本轮对缩放策略的任何变化需要单独讨论。
- 解释、追问、会话历史、手动收藏、草稿和失败恢复的既有产品规则继续适用。
- 浏览器原型、静态代码核对、隔离宿主检查和真实 Windows 操作属于不同的证据，互不替代。

## 第一轮确认

以下为已采纳的设计方向，实施状态以 `DESIGN.md` 和正式界面为准。

| 编号 | 决定 | 具体含义 |
| --- | --- | --- |
| 一 | 保留已确认方向并精修 | 保留「随手浮窗」、纸白／墨绿、小窗／双栏阅读结构和已验收默认尺寸；统一图标、字体层级、间距、按钮及状态反馈，历史、收藏、设置沿用同一套规则。 |
| 二 | 允许重绘产品图标 | 保留「拾译 PickGloss」名称；探索小尺寸可识别的专属符号，统一应用图标、托盘、悬浮球和划词入口的视觉关系；功能按钮使用统一线性图标。最终符号尚未选定。 |
| 三 | 轻快、克制，局部带一点弹性 | 按钮和收藏反馈可有轻微弹性；菜单、上下文折叠与宽窄切换平稳衔接；尺寸变化保持文字清晰和阅读位置稳定，连续操作可打断动画；时长通过可操作样机调校。 |
| 四 | 手动移动直接跟手 | 悬浮球整球可拖，点击打开菜单；解释窗口通过标题栏拖动；直接跟手、松手停住。贴边与位置记忆规则见第二轮确认。 |

## 已核对的实现事实

本节来自 2026-10-16 实施之前对正式源码的只读核对，保留为变更前的事实，不代表本轮完成后的实现；未据此宣称真实 Windows 手感通过。

- 划词入口、悬浮球、解释窗口为三种不同的界面。悬浮球当前仅外圈可拖，中心「拾」字按钮打开菜单。
- 功能图标来自 `src/renderer/app.js` 的内嵌 SVG 路径；标题标记、悬浮球和托盘品牌图形分别绘制，尚未共享一份品牌素材。
- 已有按钮悬停和按压反馈；上下文折叠及宽窄布局切换没有完整的连续过渡。
- 悬浮球与解释窗口移动由原生窗口拖动处理；按钮切换尺寸通过原生窗口几何调整完成。仅添加页面样式过渡不能证明原生窗口尺寸变化已经平滑。
- 当前内容随窗口宽度进行整体缩放，并在宽度达到分界值时切换材料／回答的布局。该策略需要与新的阅读清晰度目标一并讨论。
- 悬浮球位置、解释窗口位置和两种自定义尺寸均未跨应用重启保存；同一进程中的隐藏与再次显示通常沿用现有窗口。固定目前只影响失焦隐藏，新的划词仍会将解释窗口放到新选区附近。
- 宽窄切换当前沿用回答区域的滚动像素值；两种布局的内容排布不同，像素值相同并不能证明还在阅读同一段话。上下文折叠状态保留在当前界面节点中，并非持久会话字段。
- 打开窗口、切换视图与恢复默认尺寸时已有工作区范围限制；未发现显示器移除或工作区变化时主动恢复悬浮球／解释窗口位置的监听。

## 第二轮确认

以下为已采纳的交互规则，实施状态以 `DESIGN.md` 和正式界面为准。

| 编号 | 决定 | 规则与取舍 |
| --- | --- | --- |
| 五 | 窗口缩放与文字缩放的关系 | 保留已确认的默认窗口尺寸，将整体等比缩放调整为小窗／阅读视图两档字号和控件规格；同一布局内拉伸主要改变换行和可见内容。取舍是在小窗里可能少显示几行，换取文字与点击目标清楚稳定。 |
| 六 | 贴边吸附与贴边隐藏 | 本轮保留自由摆放，保证球和窗口可找回、可拖回；不自动吸附或贴边隐藏。取舍是暂不增加桌面边缘收纳方式。 |
| 七 | 位置与尺寸记忆 | 跨重启记住悬浮球位置、解释窗口上次位置及两种自定义尺寸；手动打开沿用上次位置，未固定时新的划词仍靠近新选区，固定窗口遇到新划词保持原位。屏幕变化时恢复到可见工作区；恢复默认大小仍只重置两种尺寸。固定窗口保持原位是本轮提出的新规则，当前实现尚不具备。 |
| 八 | 产品符号语义方向 | 采用「选区＋释义气泡」：以简洁的选区边角与气泡关系表达选中后理解。只深化这个方向，不继续制作「拾」字几何化或「纸页／书签」分支。具体图形通过实际尺寸检查。 |

## 关键交互样机

样机保留在本机，用于确认选定图标、两档排版、窗口展开收窄、上下文折叠、模式指示与拖动手感，不进入公开仓库。

- 使用既有纸白、墨绿和字体家族。初始规格为小窗正文 14 像素、阅读视图正文 16 像素；辅助文字至少 13 像素；桌面图标按钮点击区域至少 28 像素。具体取值为 Agent 设计提案，等用户看图后确认。
- 外框连续变形；打开与关闭互为逆过程；内容保持可读，不叠放两张不同缩放的旧新截图。用户快速反向操作时从当前画面继续。
- 拖动过程不施加延迟和惯性；点击与拖动使用移动阈值区分。减少动态效果时状态直接到位。
- 样机使用固定阅读材料、预设回答和独立的浏览器存储；不读取正式会话，不调用模型，不修改系统窗口或系统设置。
- 浏览器内的拖动和外框变化仅验证页面内交互。原生窗口、托盘、多屏及 DPI 体验仍需正式实现后的 Windows 验证。

样机已完成一轮独立视觉评审，并按意见细化 16 像素图标与小窗滚动边缘。主代理完成了三轮最终快速切换、草稿与保存异常等页面内检查。详细证据与未验证范围保留在本机验收归档，不进入公开仓库。本次具体图形、两档字号数值和动效节奏尚待用户看过样机后确认。

## 决策树

- 已确认的方向与范围 → 字号和控件随窗口变化的策略 → 展开收缩与阅读位置的连续性。
- 已确认允许重绘图标 → 专属符号的语义方向 → 必要时提供实际尺寸候选 → 选定后完成应用、托盘、悬浮球和划词入口适配。
- 已确认手动移动直接跟手 → 贴边与隐藏规则、位置记忆 → 屏幕空间不足和显示器变化时的恢复行为。
- 已确认动效气质 → 出场、折叠、模式切换及尺寸变化的动作规则 → 通过关键动效原型确定具体节奏。
