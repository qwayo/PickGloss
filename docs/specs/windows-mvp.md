# 拾译 PickGloss Windows MVP 规格

整理日期：2026-10-16（Asia/Shanghai），2026-10-22 整理为公开交付说明。本规格描述当前验证版的产品边界、实现约定与测试口径，不公开内部验收记录、候选指纹或过程工单。

支持范围以 Windows 11 x64、单屏环境和本文列出的固定场景为基线。未在当前发行验证中覆盖的应用、输入法、显示缩放、多显示器和模型组合，不自动纳入正式支持承诺。

## 问题陈述

用户阅读浏览器网页、PDF 和办公文档时，常遇到需要翻译、理解语境或解释的词、句子、技术名词与图像。反复切换到其他工具、复制材料和重新说明背景会打断阅读；解释与追问若没有连同材料保存，之后也难以找回。

Windows 应用能提供的选区与段落并不一致。把整页误当作段落、把截图兜底当作成功划词，或者在独立释义中混入另一模式的上下文，都会使用户误解实际发送了什么、回答依据是什么。用户需要明确的采集边界、可主动使用的降级入口，以及不影响原软件选区和剪贴板的工作方式。

PickGloss 已有可运行的验证版和针对性测试。本规格将已实现行为整理为统一依据，并区分自动化、隔离宿主检查、便携包核验和仍需真实设备验证的边界。

## 方案

提供 Windows 11 x64、单屏环境下的桌面阅读助手。用户通过托盘、可隐藏悬浮球、普通划词入口、手动粘贴或快捷键截图进入解释会话，在紧凑浮窗或阅读视图中获得解释和继续追问，再通过本地会话历史与手动收藏重新查阅。

文字提供「语境解释」和「独立释义」两个模式，分别保留回答、追问及草稿。截图先预览，再由用户直接解释或附加截图说明。用户配置一个文字 AI 服务和可选的独立识图服务，材料仅在约定的主动操作后发往所选服务。

本地会话在接纳材料时保存，不等待 AI 成功。会话标题独立于原始材料；关键词查找覆盖所有已保存材料及各模式问答；历史按问答活动排序。手动收藏标记整个会话，删除时将整条会话及截图移入 Windows 回收站，还原后可刷新重新打开。

首版应用基线为 Edge 网页、Edge 内置 PDF 阅读器和 Microsoft Word，支持承诺限于明确记录的材料与场景。入口采用已接受的屏幕固定位置行为。最终交付必须另行完成最终包验证、性能测量与用户验收。

## 用户故事

### 入口、窗口与阅读

依据：已经归档的交互决定、交付与生命周期决定及窗口默认大小确认。

1. 作为阅读者，我希望手动启动后看到面板并让程序常驻托盘，以便随时开始解释。
2. 作为阅读者，我希望从托盘或悬浮球打开常用入口，以便在不同软件之间继续使用拾译。
3. 作为阅读者，我希望能拖动或隐藏悬浮球，以便减少对原软件的遮挡。
4. 作为阅读者，我希望能暂停普通划词入口，以便在不需要解释时继续正常选字。
5. 作为阅读者，我希望关闭面板后程序仍在托盘中运行，以便再次唤起而无需重启。
6. 作为阅读者，我希望未固定的面板失焦后隐藏、固定后保持可见，以便按当前阅读任务选择窗口行为。
7. 作为阅读者，我希望固定时仍可主动关闭面板并从入口重开，以便保留控制权和会话内容。
8. 作为阅读者，我希望拖动和调整窗口大小后回答与草稿仍保留，以便自由安排屏幕空间。
9. 作为阅读者，我希望在紧凑小窗与左侧材料、右侧回答的阅读视图之间切换，以便兼顾快速解释和较长内容阅读。
10. 作为阅读者，我希望默认小窗为 300 × 483、阅读视图为 860 × 690 逻辑像素，以便使用已经确认的窗口尺寸。
11. 作为阅读者，我希望字体和控件随窗口宽度调整、靠边展开时尽量保留相邻边缘并限制在工作区内，以便内容清楚且不会突然跳离阅读位置。
12. 作为阅读者，我希望一键恢复两种视图的默认大小且保留当前布局、会话和草稿，以便撤销尺寸调整。
13. 作为阅读者，我希望恢复窗口大小立即生效且不提交 AI 设置表单，以便独立调整窗口。
14. 作为阅读者，我希望快捷键冲突时仍能使用托盘入口并看到提示，以便继续完成任务。

### 普通划词、上下文与降级

依据：已经归档的采集与模式决定及采集探针结论。

15. 作为阅读者，我希望普通划词保留原软件选区且不出现截图遮罩，以便继续熟悉的阅读操作。
16. 作为阅读者，我希望松开鼠标并取得有效选中文字后才显示附近入口，以便决定是否解释。
17. 作为阅读者，我希望点击划词入口才接纳本次材料并在条件满足时请求解释，以便普通选择本身不触发 AI 调用。
18. 作为阅读者，我希望入口保持最初屏幕位置、滚动不移动或隐藏且不自动超时，以便沿用当前已接受的桌面行为。
19. 作为阅读者，我希望点击入口外部、按 Esc 或重新划词时取消或替换旧入口，以便避免解释过期的选区。
20. 作为阅读者，我希望文字、短语、句子、中文和技术名词都可作为选定内容，以便处理真实阅读材料。
21. 作为阅读者，我希望语境解释只使用可信的所在段落，以便理解当前用法而不默认发送整页。
22. 作为阅读者，我希望选定内容、上下文及来源分别呈现，以便判断回答依据。
23. 作为阅读者，我希望无法取得可信段落时看到具体缺失提示，以便知道哪些材料尚未获得。
24. 作为阅读者，我希望上下文缺失时能补充精简段落或使用独立释义，以便继续理解内容。
25. 作为阅读者，我希望过长选区或段落得到明确提示且不静默截断，以便自行决定如何缩短材料。
26. 作为阅读者，我希望超限划词仍保留可点击提示入口，但不创建无效会话或发送请求，以便理解未能解释的原因。
27. 作为阅读者，我希望空选区、不可选文字或无权限访问时不会被当作成功采集，以便避免使用错误材料。
28. 作为阅读者，我希望普通划词不模拟复制快捷键、不改动剪贴板，以便保持原来的编辑状态。
29. 作为阅读者，我希望无法普通划词时可主动复制粘贴或截图，以便仍然完成解释。

### 截图框选与截图说明

依据：已经归档的截图范围决定与材料留存决定。

30. 作为阅读者，我希望通过截图入口进入变暗遮罩和框选模式，以便明确选择屏幕上的图像区域。
31. 作为阅读者，我希望首版在鼠标所在的单个显示器中框选，以便使用清楚的采集范围。
32. 作为阅读者，我希望完成框选后先预览图片，再选择是否解释，以便检查截图是否准确。
33. 作为阅读者，我希望可以直接解释截图，也可以附加文字说明后解释，以便表达关注对象或具体问题。
34. 作为阅读者，我希望只发送裁剪图片、主动添加的说明和截图模式对话，以便框外内容不被自动使用。
35. 作为阅读者，我希望截图模型无法辨认时说明不确定，以便不把猜测当作已读内容。
36. 作为阅读者，我希望在框选完成前取消不产生会话，以便放弃未完成的采集。
37. 作为阅读者，我希望完成框选后的未解释预览也被保存，再次框选不丢弃旧预览，以便稍后继续处理。
38. 作为阅读者，我希望在已打开的 PDF 或 Word 中直接采集可见内容，以便不用先导入完整文件。
39. 作为阅读者，我希望无文字层材料能通过截图解释，并明确它属于截图兜底，以便了解实际使用的能力。
40. 作为阅读者，我希望截图超出 15 MiB 时得到缩小范围的提示，以便主动控制输入体积。

### 解释模式与会话连续性

依据：已经归档的模式隔离决定，以及调用时机与恢复决定。

41. 作为阅读者，我希望有可信上下文和可用模型时，点击划词入口直接进入语境解释，以便快速理解当前材料。
42. 作为阅读者，我希望独立释义仅依据选定内容提供一般含义或翻译，以便区分通用用法与当前语境。
43. 作为阅读者，我希望独立释义不接收原段落或语境模式对话，以便两种解释依据确实隔离。
44. 作为阅读者，我希望首次切到尚无回答的另一文字模式时先看到「开始释义」，以便主动决定新调用。
45. 作为阅读者，我希望切回已有模式或重新打开历史时复用原结果，以便不重复请求或丢失记录。
46. 作为阅读者，我希望两种文字模式分别保存回答、追问和未发送草稿，以便随时来回比较。
47. 作为阅读者，我希望切换会话、模式或页面时延迟保存仍归属于原会话与模式，以便输入不串用。
48. 作为阅读者，我希望主动重新解释时在当前模式追加新回答并保留原回答，以便比较前后结果。
49. 作为阅读者，我希望失败重试不重复追加同一条用户追问，以便保持清楚的问答顺序。
50. 作为阅读者，我希望每次采集形成独立解释会话，即使材料相同也不自动合并，以便保留每次阅读记录。
51. 作为阅读者，我希望恢复中断会话后看到已保存片段且不自动续发请求，以便自主决定下一步。

### AI 配置、材料发送与隐私

依据：已经归档的 AI 服务完整决定。

52. 作为使用者，我希望填写服务地址、模型名称和可选密钥，连接 OpenAI 兼容的文字服务，以便选择自己的云端或本机模型。
53. 作为使用者，我希望远程服务使用 HTTPS，本机 localhost、127.0.0.1 或 ::1 可以使用 HTTP，以便连接符合首版协议范围的服务。
54. 作为使用者，我希望可单独配置识图模型，以便选择具备图像输入能力的服务。
55. 作为使用者，我希望识图模型名留空或仅为空白时，截图解释、追问和连接测试完整沿用文字服务配置，以便减少重复设置。
56. 作为使用者，我希望识图页残留的地址或密钥不与文字配置拼接，以便不会把请求发到错误服务。
57. 作为使用者，我希望明确填写独立识图模型后，缺配置或调用失败会提示而不暗中切换服务，以便知道实际使用了什么。
58. 作为使用者，我希望文字连接测试发送短文字、识图连接测试发送内置小图，以便确认实际请求链路可用。
59. 作为使用者，我希望模型不支持图片或配置缺失时仍保留材料，以便调整配置后继续解释。
60. 作为使用者，我希望界面显示实际使用的模型并提供设置入口，以便核对服务选择。
61. 作为使用者，我希望 API Key 使用 Windows 加密保存且不以明文返回界面，以便妥善保存凭据。
62. 作为使用者，我希望改变服务来源时重新填写或明确清除旧密钥，以便旧密钥不会自动送到新来源。
63. 作为使用者，我希望仅主动解释、追问或测试连接时发送约定材料，以便没有后台批量上传。
64. 作为使用者，我希望了解会话和截图是本地普通文件且不做云端历史同步，以便作出合适的数据保管安排。
65. 作为使用者，我希望调试日志和错误提示不泄露密钥、原始请求或私密上游响应，以便故障信息不暴露材料。
66. 作为阅读者，我希望模型把选定内容、段落及图片中的文字当作待解释材料，以便材料中夹带的指令不会改变助手职责。

### 回答、追问与失败恢复

依据：已经归档的输出与失败规则，以及 Markdown 追加需求。

67. 作为阅读者，我希望默认中文回答先给主要意思、再简要说明依据，以便快速理解。
68. 作为阅读者，我希望通过追问要求翻译或调整详略，以便不增加第三个文字模式也能满足需要。
69. 作为阅读者，我希望回答区分材料证据与一般知识，证据不足时说明不确定，以便不误信未提供的原文或来源。
70. 作为阅读者，我希望流式看到回答，并能单击停止使文字不再增长，以便及时控制生成。
71. 作为阅读者，我希望失败、中断或停止后保留已有片段并标为未完成，以便内容不会突然丢失。
72. 作为阅读者，我希望未完成回答不会作为下一次请求的完整依据，以便后续解释不把残缺输出当成定论。
73. 作为阅读者，我希望停止后仍可继续追问，且原片段、新问题和新回答都能重新打开，以便延续阅读。
74. 作为阅读者，我希望连接测试在 15 秒、解释请求在 60 秒超时后明确结束等待，并由自己手动重试，以便不发生后台重复调用。
75. 作为阅读者，我希望选定文字、段落、追问或说明以及单次请求总量的限制都明确提示，以便缩短材料而不是遭到静默裁剪。
76. 作为阅读者，我希望新回答、历史回答和停止片段以 Markdown 显示，以便阅读标题、列表、表格、引用与代码。
77. 作为阅读者，我希望每条回答能复制其原始 Markdown，包括已有的流式或停止片段，以便保留标记、换行和代码围栏。
78. 作为阅读者，我希望复制成功或失败有明确反馈且复制目标不串会话、模式或消息，以便知道自己取得了哪段回答。
79. 作为阅读者，我希望回答中的 HTML 不执行、远程图片不自动加载，网页链接由我主动打开，以便生成内容不会自行触发外部操作。
80. 作为阅读者，我希望中文输入法确认候选不误发送，Shift+Enter 换行、Enter 只发送一次追问，以便可靠输入多行问题。
81. 作为阅读者，我希望持续输出不破坏输入焦点、阅读位置和停止或复制按钮的点击，以便边读边操作。
82. 作为阅读者，我希望输入区保持已确认的简洁样式，不显示已要求移除的辅助小字，以便减少干扰。

### 会话历史、手动收藏与恢复

依据：已经归档的会话管理决定与最小实现记录。

83. 作为阅读者，我希望点击采集入口、提交粘贴内容或完成截图框选后立即保存本机会话，以便不依赖解释成功才留存材料。
84. 作为阅读者，我希望未配置服务、未解释、失败和停止的会话都出现在历史中，以便之后继续处理。
85. 作为阅读者，我希望重新打开会话时保留材料、来源、各模式问答和草稿，以便恢复阅读上下文。
86. 作为阅读者，我希望收藏标记整个解释会话，以便把它作为持续补充的知识条目。
87. 作为阅读者，我希望收藏后的继续解释与追问仍保存在同一会话，以便知识条目随使用更新。
88. 作为阅读者，我希望取消收藏仅移除标记、不删除历史，以便随时调整整理方式。
89. 作为阅读者，我希望在全部会话和手动收藏之间切换并继续追问，以便快速找到要读的材料。
90. 作为阅读者，我希望会话初始标题由选定文字或截图说明生成且可以独立改名，以便更容易辨认。
91. 作为阅读者，我希望改名不修改原文、截图说明、截图和问答，以便保留采集事实。
92. 作为阅读者，我希望流式回答仍在保存时改好的标题不会被覆盖，以便整理操作稳定生效。
93. 作为阅读者，我希望关键词搜索覆盖标题、选定文字、上下文、截图说明及所有模式已保存的问答，以便找到真正相关的会话。
94. 作为阅读者，我希望查找也能命中未完成片段和当前未显示的模式，但不把未发送草稿当成已保存问答，以便结果符合材料状态。
95. 作为阅读者，我希望全部会话和收藏都能使用本地关键词查找且不调用 AI，以便快速查找而无需联网。
96. 作为阅读者，我希望分批显示时搜索仍覆盖全部记录，并能继续加载结果，以便不因列表长度漏掉历史。
97. 作为阅读者，我希望历史按最近解释或追问排序、无问答会话按建立时间排序，以便最近使用的材料更容易找到。
98. 作为阅读者，我希望浏览、模式切换、收藏、改名、草稿和同一回答的流式保存不改变问答顺序，以便列表不会因整理或生成片段反复跳动。
99. 作为阅读者，我希望旧版本会话仍可读取，缺少精确问答时间时有明确兼容处理，以便已有历史不被误写或丢弃。

## 实现决定

以下区分已确认产品规则与沿用的实现方式。实现方式可以在保持外部契约和兼容性、通过相应验证的前提下调整；不得把实现细节反向改写为新的用户需求。本节不规定具体代码文件位置。

1. **桌面技术路线。** 沿用 Electron、原生 HTML／CSS／JavaScript 界面、selection-hook 取词组件和 C# UIA 选区／段落复核。选区采集运行在独立进程；主进程负责会话、请求、存储及桌面操作，界面通过受限的 preload 动作接口交互。不引入浏览器扩展。早期关于 React 的技术比较不改变当前实现路线。
2. **采集可信性。** 选中文字和所在段落分别核验；上下文必须与本次选区对应，不可信时保留可用选定内容并明确降级。普通划词禁用自动复制回退；失败出口为主动粘贴或截图。过长选区保留提示入口，但不能创建有效解释或发送请求。正确性优先于入口速度目标。
3. **屏幕固定入口。** 沿用跟随实验回退后的行为：保留初始屏幕位置，滚动不移动、不隐藏、不自动超时；主动取消或新采集使旧入口失效。入口仍解释该次接受的材料。原文跟随失败保留为失败证据，不把它写成已修复能力。
4. **会话接纳与身份。** 点击有效文字入口、提交粘贴内容、完成有效截图框选即创建并保存会话；采集身份独立于文本是否相同。截图完成前取消不建会话，完成后预览属于已保留材料。用户尚未配置服务或请求失败均不撤销已接纳会话。
5. **材料与模式。** 文字会话有语境解释和独立释义；截图会话使用截图解释。各模式独立保存消息、状态、错误和草稿。已有记录重开不自动请求；另一文字模式首次进入显示主动开始入口。重新解释追加回答，手动重试不重复用户问题。沿用当前约束：已用于问答的上下文或截图说明不被直接改写；修改材料新建会话或通过追问补充，避免旧回答失去其依据。产品依据和材料编辑限制均来自已归档决定与当前实现。
6. **服务路由与协议。** 使用 OpenAI 兼容的 `/chat/completions`，一个文字配置和一个可选独立识图配置。只根据识图模型名称是否为空决定整套沿用，不混合地址、模型和密钥。独立配置缺失、调用失败或缺少图片能力时明确报错，不自动换服务。连接测试使用真实短文字或内置小图请求。
7. **请求材料契约。** 语境解释发送选定内容、可信所在段落及本模式历史；独立释义仅带选定内容与独立模式历史；截图带裁剪 PNG、截图说明及截图历史。未完成助手回答不作为后续请求的完整依据。内置中文提示词要求引用材料不得覆盖助手规则，并说明证据不足；不宣称提示词能保证所有模型绝不误答。
8. **限长与失败恢复。** 选定文字 12,000 字符、段落 6,000 字符、追问或截图说明 4,000 字符、单次全部文字材料与历史预算 40,000 字符、裁剪 PNG 15 MiB。沿用当前字符长度检查口径；这不是模型 token 上限。超限提示缩短，不静默截断。连接测试 15 秒、解释 60 秒超时；失败／截断／停止保留片段并标记未完成，手动重试，恢复历史不自动续发。
9. **密钥与发送边界。** 远端使用 HTTPS，本机回环地址允许 HTTP；Key 可选，通过 Windows 加密保存。默认界面状态不含明文 Key。改变来源必须重新输入或明确清除旧 Key；保留拒绝请求重定向的既有协议保护。不记录带原始请求、响应或 Key 的调试日志，不直接展示上游私密响应。正常历史保存与调试日志分开。产品依据来自已归档决定，重定向保护沿用现有协议测试。
10. **窗口与编辑。** 采用 A「随手浮窗」及后续确认的双布局；小窗 300 × 483、阅读视图 860 × 690 逻辑像素，保留自由调节及尺寸记忆。恢复默认大小同时清除两种尺寸记忆、立即恢复当前布局，保留位置边缘并限制在工作区内，不保存 AI 表单或改动草稿。未固定失焦隐藏，固定时保留，主动关闭仍隐藏。输入法组合期间不发送；保留 Enter／Shift+Enter 行为及已确认的简洁输入区。窗口和输入依据均来自已归档决定。
11. **Markdown 与复制。** 三种解释中的回答、历史和未完成片段使用 Markdown 排版，支持标题、强调、列表、引用、表格、代码和网页链接。每条回答通过所属会话、模式、消息定位复制原始文本。HTML 按文字处理，远程图片不自动加载，外链主动打开；不包含公式或扩展图表渲染。流式更新保留交互控件与输入状态，避免鼠标按下至松开之间的重绘导致点击丢失。
12. **本地存储契约。** 沿用独立用户数据目录、设置文件、逐会话 JSON 与裁剪图片。会话保留身份、创建时间、普通更新时间、问答活动时间、独立标题、材料及上下文来源／缺失原因、来源信息、收藏标记、当前模式及各模式消息／草稿。只有密钥加密；会话和截图是普通本地文件。不做云端历史同步、按天数清理或按条数清理。
13. **标题、索引与分页。** 标题独立更新，流式持久化不得用旧标题快照覆盖改名。沿用当前 1 至 200 字符有效标题约束，未改名时从材料生成显示标题。主进程维护包含全模式已保存问答的本地关键词索引，界面接收结果摘要；未发送草稿不进索引。当前为不区分大小写的连续关键词匹配、每批显示 50 条；这些是现有实现方式，不把批次当作保存上限或搜索范围。规则和源码阶段记录来自已归档决定与当前实现。
14. **问答活动与旧格式。** 只有新增解释或追问消息推进问答活动；同一回答继续流式保存不推进。无问答以创建时间排序；其他整理操作不改变活动时间。旧记录缺少精确问答时间时，有问答用原更新时间作兼容近似，无问答用创建时间；只读加载不改写文件，首次正常保存固定兼容值。不能把近似值描述为运行时对历史精确问答时间的还原。规则和兼容记录来自当前实现。
15. **收藏、删除和还原。** 收藏只改整会话标记；取消收藏保留完整历史。确认删除后通过系统回收站处理会话目录和截图，失败时保留数据，无永久删除回退。还原到原位置后，重新进入历史、历史页恢复窗口焦点或手动刷新触发目录重读。隔离目录恢复和真实系统回收站还原分别验收。
16. **来源信息。** 仅保留可实际取得的应用名、窗口标题和采集方式，缺失明确显示。手动粘贴、截图和普通划词的来源性质分开；不从窗口标题推断网页地址、文件路径、页码或返回位置。
17. **启动退出与可恢复交付。** 手动启动打开面板并常驻托盘；关闭面板不退出。菜单退出先确认草稿与会话保存，再释放相关资源；失败取消退出并允许修复后重试。交付完整便携目录压缩包，程序与数据分离，正常退出旧版后手动更新并保留旧包。数据结构变化须提供可恢复处理与实际验证，不预先承诺任意降级兼容。
18. **支持与性能。** Windows 11 x64、单屏，Edge 网页、Edge PDF、Word 的明确场景为首版基线。1,000 条混合会话为性能验收规模而非数据上限；历史打开与关键词搜索各自至少 95% 在 1 秒内完成，正确划词入口在 500 毫秒内出现。冷启动、CPU、内存和模型响应单独实测，无新增固定数值门槛。无法达标时保留问题并修复或重新讨论，不降低标准来宣称完成。

## 测试决定

### 已确认的测试边界

优先从用户动作及其可观察结果验证，复用已有入口。**核心自动化以应用现有会话动作入口为主要边界**：执行创建、解释、追问、改名、搜索、收藏、删除、刷新和重开，检查返回状态、实际隔离目录内容、重建存储后的恢复结果以及发出的模型请求材料。网络和桌面宿主在既有边界使用可控替身或本机测试服务，避免用内部缓存结构、函数调用顺序或私有 DOM 细节作为功能通过标准。

现有工程已具备真实主进程代码配合隔离存储的动作测试、提供商协议测试、真实 Electron 渲染器配合模拟 IPC 的交互检查，以及 Windows 宿主检查。它们分别复用，不把多段测试拼称为已存在的一条完整端到端测试。

如最终包验证需要贯通正式 renderer、preload、主进程和存储，**只在应用启动层补充可控的隔离数据／测试服务装配入口**，通过现有用户动作完成主路径；不为每个模块增加专用测试 API。此项是拟补齐的测试装配能力，当前不宣称已实现。正常使用仍走原有数据与服务配置。

操作系统采集、真实回收站还原和真实模型能力不能由上述替身证明，需在最终包中使用固定样本、真实 Windows 应用及明确记录的服务配置验收，并由用户确认交互体验。当前只整理测试方案，不启动这些执行工作。

### 行为验收场景

以下是后续实现和验收应覆盖的外部行为；本清单不表示本次运行或通过了测试。

1. **划词主路径：** 在支持场景选中目标文字，鼠标释放后出现正确入口；仅点击后接纳材料及按条件解释；段落不包含邻段或相邻单元格；关闭后继续阅读或编辑。
2. **入口生命周期：** 滚动后保持屏幕位置且不自动超时；点击空白、Esc、重新划词以及其他主动入口操作按当前规则取消或替换；旧采集结果迟到不覆盖新选区。
3. **采集降级：** 空选区、访问失败、不可信／过长段落与超限选区分别给出正确状态；普通划词不模拟复制，用户仍可使用粘贴或截图。
4. **截图：** 用四角及框外标记核对裁剪，仅裁剪区域进入会话与请求；预览、可选说明、完成前取消和完成后重新框选符合留存规则。图像 PDF 使用截图证据单独记录。
5. **发送矩阵：** 为选定文字、段落、每种模式历史、草稿和框外内容设置不同标记，核对真实构造出的请求；独立释义不含原段落或另一模式历史，截图不含框外材料，草稿不被自动发送。
6. **调用时机：** 普通选择、切回已有结果、历史重开、模式切换和应用重启不自动发送；首次另一模式需主动开始，重新解释保留旧回答；失败重试不重复用户问题。
7. **服务配置：** 识图模型空白时完整沿用文字配置且忽略残留识图字段；独立配置优先且失败不暗换；测试连接使用当前表单对应配置与实际短文字／小图。
8. **凭据与协议：** 用虚构 Key 检查加密落盘、界面不返回明文、跨来源必须重填／清除、远端 HTTP 与重定向拒绝、日志和错误不泄露私密数据。
9. **限长：** 每项上限内及刚越界分别测试，不把字符额度当 token 额度；超限不调用模型、不静默丢弃材料。段落缺失原因补充成功后清除。
10. **流式、停止和失败：** 在鼠标按下与松开之间插入流式片段，单击停止仍生效；取消、超时、网络截断和上游失败保留片段并显示未完成；不会自动重试或继续使用未完成回答作完整依据。
11. **Markdown 与复制：** 检查新回答、历史、停止片段及各模式；复制原文逐字保留标记和换行，目标绑定正确；HTML 不执行、远程图片不加载，外链仅主动打开，复制失败可见。
12. **草稿与输入：** 两种文字模式草稿及不同会话输入互不串用；保存延迟或切换期间仍归属正确；输入法确认不误发送，多行追问只发送一次，流式时焦点和阅读位置保留。
13. **窗口：** 固定／取消固定、失焦、主动关闭、重开、拖动、自由调节、宽窄切换和靠边展开符合当前约定；恢复默认同时覆盖两种尺寸，不提交设置或丢失草稿。
14. **会话留存与收藏：** 采集即保存，未解释、缺配置、失败／停止和重复材料均保留；收藏后追加问答属于同一会话，取消收藏仍有完整历史，不按数量或天数自动清理。
15. **标题、搜索和排序：** 改名不改材料且不被后台保存覆盖；搜索覆盖全部已保存字段、所有模式及未加载行，收藏筛选不缩小字段范围；整理动作和流式落盘不改变问答活动顺序。
16. **旧数据兼容：** 旧格式读取前后文件保持不变；首次正常保存固定兼容时间；无问答用创建时间，旧问答近似时间明确记录；新数据重建存储或重启后保持标题、问答、草稿和截图。
17. **删除和恢复：** 取消确认不删除；成功删除同时处理会话及截图；回收站失败保留数据；隔离目录恢复分别验证重进历史、恢复焦点和手动刷新。另行由真实系统回收站还原到原位置，检查材料、标题、各模式问答和截图完整可读。
18. **退出与故障：** 退出先保存全部待存草稿和材料；保存确认超时或写盘失败取消退出、保留可重试状态；相关进程与资源在成功退出后结束。此类故障使用隔离注入，不破坏真实用户数据。
19. **最终包与手动更新：** 记录完整包标识及文件核对结果，确认原生助手和运行依赖；使用隔离旧数据完成正常退出、运行新包和内容核对，保留旧包及恢复材料；不只检查可执行文件或数据目录名称。
20. **最终真实闭环：** 最终包在已承诺场景与明确服务配置上完成采集／截图、解释、追问、历史重开、收藏后追问、重启、失败／停止／手动重试和删除／还原；将普通划词、降级和截图分别记录，用户确认最终范围后再关闭实现任务。

| 项目 | 样本与计时 | 判定和记录 |
